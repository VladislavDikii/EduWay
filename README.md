# EduWay: контракт запитів фронтенд-бекенд

Версія 1 для SCRUM-44. Документ описує, які запити є, що надсилається і що повертається. Його треба погодити всією командою до підключення фронтенду.

## Загальне

- **Адреса бекенду.** Локально `http://127.0.0.1:8000`. Змінюється лише `baseUrl` у `api_service.dart` і `auth_service.dart`.
- **Формат.** JSON, кодування UTF-8. У Flutter відповідь читати так: `jsonDecode(utf8.decode(response.bodyBytes))`, інакше українські літери зіпсуються.
- **Помилки.** Код HTTP і тіло `{"detail": "текст помилки"}`.
- **Запуск** 1. При першому запуску
  1. docker run -d --name eduway-db -e POSTGRES_USER=eduway -e POSTGRES_PASSWORD=eduway -e POSTGRES_DB=eduway -p 5432:5432 postgres:16
  2. pip install fastapi uvicorn "psycopg[binary]" pydantic
  uvicorn main:app --reload --port 8000
  3. pip install python-docx
  python import_questions.py
  4. flutter pub get
  flutter run -d chrome

2.При наступних запусках
    2.1. docker start eduway-db
  cd backend
  cd py
  uvicorn main:app --reload --port 8000

  2.2. cd "frontend\first step"
  flutter run -d chrome
- **Користувач.** Токена поки нема. Після входу додаток запам'ятовує `username` і надсилає його в запитах про квитки. Пізніше це замінимо на токен.
- **Індекси варіантів.** Варіанти відповіді нумеруються з нуля: `0` це перший варіант, `3` це четвертий.
- **Перевірка вручну.** Усі запити можна спробувати на сторінці `/docs` бекенду.

## Авторизація

### POST /api/register

Створює акаунт.

Тіло запиту:

```json
{"username": "vlad", "password": "123456"}
```

Ім'я від 1 до 50 символів, пароль від 6 до 128.

Відповіді:

- `201`: `{"message": "registered", "username": "vlad"}`
- `409`: ім'я вже зайняте
- `422`: порожні поля або пароль коротший за 6 символів

### POST /api/login

Тіло запиту таке саме, як у реєстрації.

Відповіді:

- `200`: `{"message": "ok", "username": "vlad"}`. Після цього додаток запам'ятовує `username`.
- `401`: невірне ім'я або пароль
- `422`: некоректні дані

## Предмети і теми

### GET /api/subjects

Список предметів.

```json
[{"id": 1, "name": "Математичний аналіз", "questions": 45},
 {"id": 2, "name": "Історія України", "questions": 32}]
```

### GET /api/subjects/{subject_id}/topics

Теми предмета, за порядком.

```json
[{"id": 1, "pos": 1, "name": "Границі та неперервність функцій", "questions": 11}]
```

Назву теми на екрані складати так: `Тема {pos}: {name}`. Якщо предмета немає, відповідь `404`.

## Перегляд питань

### GET /api/topics/{topic_id}/questions

Питання однієї теми з правильними відповідями (екран «Переглянути»).

```json
[{
  "id": 1, "topic_id": 1, "topic": "Границі та неперервність функцій",
  "topic_pos": 1, "pos": 1,
  "text": "Чому дорівнює границя lim(x→2)(x+3)?",
  "options": ["3", "4", "5", "6"],
  "correct_index": 2
}]
```

Правильна відповідь це `options[correct_index]`. Якщо теми немає, відповідь `404`.

### GET /api/subjects/{subject_id}/questions

Усі питання предмета, відсортовані за темою і номером. Формат елементів такий самий. Якщо предмета немає, відповідь `404`.

Відповідність полів у `TestScreen`: `text` це `question`, `correct_index` це `correctIndex`, `options` без змін.

## Квитки

### POST /api/tickets/draw

Створює квиток: випадкові питання однієї теми.

Тіло запиту:

```json
{"username": "vlad", "topic_id": 1, "count": 5, "no_repeats": true}
```

- `count` від 1 до 50 (за замовчуванням 5). Якщо в темі питань менше, береться вся тема.
- `no_repeats` (за замовчуванням `true`): спершу питання, яких користувач ще не бачив. Коли вони закінчуються, додаються ті, що були найдавніше (починається новий круг).

Відповідь `201`. Правильних відповідей тут немає, вони приходять лише після здачі:

```json
{
  "ticket_id": 12,
  "topic_id": 1,
  "created_at": "2026-11-01T12:00:00+00:00",
  "new_round": false,
  "left_in_round": 6,
  "questions": [
    {"id": 3, "pos": 1, "text": "...", "options": ["...", "...", "...", "..."]}
  ]
}
```

- `new_round`: `true`, якщо довелося брати вже бачені питання.
- `left_in_round`: скільки ще не бачених питань лишилося в темі (`null`, якщо `no_repeats` вимкнено).

Помилки: `404` (користувача, теми або питань немає), `422` (некоректні дані).

### POST /api/tickets/{ticket_id}/submit

Здає відповіді, завершує квиток і повертає результат.

Тіло запиту:

```json
{
  "username": "vlad",
  "answers": [
    {"question_id": 3, "chosen_index": 2},
    {"question_id": 7, "chosen_index": null}
  ]
}
```

`chosen_index` від 0 до 3, або `null`, якщо питання пропущено.

Відповідь `200`:

```json
{
  "ticket_id": 12, "score": 4, "total": 5,
  "results": [
    {"question_id": 3, "chosen_index": 2, "correct_index": 2, "is_correct": true}
  ]
}
```

Помилки: `404` (квиток не знайдено або він чужий), `409` (квиток уже здано), `422` (питання не з цього квитка).

### GET /api/tickets?username=vlad&limit=20

Історія квитків користувача, найновіші першими. `limit` від 1 до 100, за замовчуванням 20.

```json
[{
  "ticket_id": 12, "topic_id": 1, "topic": "Границі та неперервність функцій",
  "created_at": "2026-11-01T12:00:00+00:00",
  "finished_at": "2026-11-01T12:05:00+00:00",
  "total": 5, "score": 4
}]
```

Якщо квиток не завершено, `finished_at` і `score` дорівнюють `null`. Якщо користувача немає, відповідь `404`.

## Як проходить тест

1. Користувач обирає предмет і тему.
2. Додаток викликає `POST /api/tickets/draw` і показує питання по одному.
3. Відповіді накопичуються в додатку.
4. Після останнього питання один запит `POST /api/tickets/{id}/submit`, у відповіді результат і правильні відповіді.
5. Квиток з'являється в історії (`GET /api/tickets`), блок «Останній квиток» бере першу його позицію.

## Відомі обмеження

- Користувач передається іменем без токена, тому хтось може підставити чуже ім'я. Для демо прийнятно, до публічного розгортання треба замінити на токен.
- Окремого запиту з деталями старого квитка (питання і відповіді) ще немає.
- Немає запитів на вихід, зміну імені, власні предмети і питання. Вони не входять у MVP.
- Кількість питань у картках предметів на головній поки написана в коді, її можна брати з `GET /api/subjects` (поле `questions`).
